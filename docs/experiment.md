# Retrieval experiment card

Dataset: [BEIR SciFact](https://github.com/beir-cellar/beir), based on the [SciFact project](https://github.com/allenai/scifact). The corpus contains paper titles and abstracts; the queries are scientific claims. The relevance labels indicate documents annotated for the retrieval task. Relevance is not the same as factual truth, clinical value, or answer quality. Unjudged items are treated as non-relevant, so incomplete judgments can penalize valid results.

Development split: the evaluation script sorts official training query IDs, shuffles with Python's random seed 42, and selects 20% for development (162 queries in the checked source data). It does not train on the test set. The optional neural model is pretrained independently; we cannot guarantee it did not encounter related content or benchmark text during pretraining.

First measured development baseline, 19 November 2026: BM25 k1=1.2, b=0.75, title plus abstract, lowercased Unicode word tokens, deterministic ID tie-breaks. At k=10, Recall 0.8241, MRR 0.6799 and nDCG 0.7109. On this developer's machine, sequential warmed search timing was roughly 23 ms median and 41 ms p95; this excludes index construction and is not a deployment SLO. Re-run for your environment. Individual query and input-hash details are produced locally by the evaluation command.

A later development comparison on the same 162 queries measured BM25 / MiniLM dense / hybrid respectively: Recall@10 0.8241 / 0.8045 / 0.8364; MRR@10 0.6799 / 0.6626 / 0.6884; nDCG@10 0.7109 / 0.6945 / 0.7216. Sequential warmed median query times were 14.63 / 16.70 / 33.64 ms, excluding model download and corpus encoding. Hybrid uses reciprocal-rank fusion with constant 60 over up to 100 candidates from each method. The paired query bootstrap used 10,000 resamples, seed 42; the 95% percentile interval for hybrid minus BM25 Recall@10 was [−0.0309, 0.0556]. It includes zero, so the observed difference does not establish a quality improvement. It describes uncertainty from resampling these queries, not different datasets or model-selection uncertainty.

The neural model was `sentence-transformers/all-MiniLM-L6-v2` at commit `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`, maximum sequence length 256, with sentence-transformers 3.4.1, transformers 4.48.3, PyTorch 2.2.2 and NumPy 1.26.4. The process used `OMP_NUM_THREADS=2`. Loading and encoding the full corpus was substantially slower than a single query and is not reflected in the query-time values. Individual queries and full reports remain local under `results/`.

The fixed BM25 baseline was also run on the official 300-query test set, before the later three-system development comparison. It produced Recall@10 0.7876, MRR@10 0.6309 and nDCG@10 0.6634. Excluding the two normalized-text overlaps gives 298 queries and Recall@10 0.7895, MRR@10 0.6318 and nDCG@10 0.6645. On an Intel Core i7-4770HQ, the test run measured sequential warmed query median 18.57 ms and p95 33.35 ms. This is one local run excluding indexing; it is not a performance guarantee.

After the development comparison, a second test run evaluated the same predefined BM25, MiniLM and RRF systems. Their test Recall@10 was 0.7876 / 0.7833 / 0.8139; MRR@10 was 0.6309 / 0.6047 / 0.6460; and nDCG@10 was 0.6634 / 0.6451 / 0.6835. Median query times were 13.28 / 16.59 / 31.96 ms, excluding indexing. For hybrid minus BM25, the 10,000-resample paired 95% percentile interval was [0.0022, 0.0517] for Recall@10 and [−0.0012, 0.0416] for nDCG@10. These are exploratory intervals across queries, without correction for multiple comparisons. They do not establish generalization to other corpora. Excluding both overlapping queries, recalls were 0.7895 / 0.7852 / 0.8160; the hybrid-minus-BM25 recall interval was [0.0019, 0.0518]. The two original overlaps, incomplete relevance labels, potential pretraining exposure, and the earlier BM25 test inspection all limit interpretation.

The measured source files had SHA-256 hashes: corpus `dec31c8182f3d744c7d2c09423756fd1d17cbef75808db13ba01cc0aab4d1ac6`; queries `8ff84a7c903f722981cd8d595c022660140c51867b27608a6d4910db86080313`; test qrels `0864bb985e0ca2367ba217977e72004d549054b2b06666ed9d4825ac7c21284c`; train qrels `a53f2114831916c096b6c37d9e54da68cef4efdcdbd5ed46533601af972acf1d`. The BM25 run used Python 3.11.15 and macOS 14.8.9.

The official train/test split has two matching query pairs after case and whitespace normalization. Both pairs have identical relevant document IDs. A full test report must disclose them. The sensitivity analysis additionally excludes those test queries; it does not detect semantic paraphrases or prevent all pretraining contamination.

Important limitations: one small scientific corpus, one query-level split, incomplete relevance judgments, long-document truncation for dense models, no access control, no online user evaluation, no generated answers, and no accuracy guarantee for new domains. No statistical or operational conclusion about deployed systems follows from this development baseline alone.
